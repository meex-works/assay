# Launch kit

For creators who want their launch to be pure: the same checklist the channel uses, and a **preflight** that runs it
against assay's indexes before anything is on-chain. It's free, it's read-only, and it never touches a key.

## What you control, and what you don't

A creator controls everything about how a coin starts. Nobody controls who buys it afterwards. Pure is a claim about
the start; a late bundle that arrives at minute 2 breaks purity no matter how clean the launch was, and the channel
says so ([pure.md](pure.md#bundles-that-arrive-after-the-post)). The kit covers the part that's yours.

## The checklist

| | do | why it matters |
|---|---|---|
| **dev wallet** | launch from a wallet funded from an exchange or a wallet with its own clean history; not from a wallet that funded other launches | the creator's funding is traced `trace_hops` back; a link to a serial creator or a bundler fails it |
| **dev buy** | buy at most `dev_buy_max` of supply (5% by default), in the create transaction, from the dev wallet only | anything else bought from your wallets in the opening slots is a bundle |
| **no extra wallets** | don't buy from second wallets, don't fund friends' wallets to buy, don't use a bundling service | assay clusters by funding *and* timing; wallets funded within minutes of each other read as one group |
| **original identity** | your own image, a fresh metadata upload, a ticker that isn't a living coin's | reused URIs, matching images and look-alike tickers fail the originality check; a dead coin's ticker is allowed and noted |
| **image from you** | art you made or have the right to, not an image lifted from the web | reverse image search finds where an image came from |
| **links that point back** | the site and the X account show the mint; every link resolves | a site showing a different mint, or nothing, fails |
| **no borrowed names** | don't imply a person, brand or project is involved unless they say so on their own accounts | an unconfirmed affiliation is an integrity flag |
| **honest fee setup** | if the description says fees go to holders, a buyback or a community wallet, the fee config does exactly that | a promise the config doesn't keep is an integrity flag |
| **no hidden supply** | no launch mode that mints supply the description doesn't mention | holders are measured net of program-held supply, and an unmentioned mode fails the config check |
| **plain text** | no instructions in the description, site or image aimed at AI reviewers | it's an integrity flag, and it's checked |

## Preflight

The creator describes the launch before it happens, and assay runs every check it can without the coin existing:

```sh
npx @assay/preflight plan.json
```

```json
{
  "name": "Lantern",
  "ticker": "LANTERN",
  "description": "…",
  "image": "./lantern.png",
  "mint": "<the public key of the mint keypair you will launch with>",
  "dev_wallet": "<public key>",
  "dev_buy_sol": 0.5,
  "links": { "x": "https://x.com/…", "telegram": "https://t.me/…", "website": "https://…" },
  "fees": { "holder_reward": false, "sharing": [] }
}
```

Or `POST /v1/preflight` with the same body. It returns each check as pass, fail or can't-check-yet, with the fix:

```
PASS  dev wallet: funded from an exchange 9 days ago, no earlier launches
PASS  dev buy: 0.5 SOL ≈ 1.8% of supply at launch
FAIL  image: perceptual match (distance 3) with $LANTRN, launched 2 days ago by another creator
PASS  ticker: no living coin uses LANTERN; one dead coin did (noted, not a fail)
FAIL  website: does not show the mint yet; add <mint> to the page
PASS  X: account exists since 2022, one handle
WAIT  alive: decided after launch
```

Only **public keys** go into a plan. The mint keypair is generated by the creator, locally, with their own tools; the
preflight only ever sees its public half, which is what lets the site show the mint before launch.

## Declared launches

A plan that passes preflight can be **declared**: assay stores it, keyed by the mint's public key. When that mint
appears on-chain, L0 compares the launch with the plan. If it matches, the link and image checks are already done and
purity is decided in seconds, not after L1. If it doesn't match (a different dev wallet, a bigger dev buy, a changed
image), the difference is reported as an observation: "launched differently from its declared plan".

A declaration doesn't buy a post. It isn't paid, it can't be paid for, and the channel posts a declared coin only if
the live checks pass, exactly like any other. Declaring gets a creator a faster, fairer check and nothing else.

## What the kit doesn't do

It doesn't launch coins. assay stays read-only: no transactions, no signing, no keys. A creator launches on pump.fun
the way they normally would, with the preflight's answers in hand. (A launch page that builds the transaction for
the creator's own wallet to sign is possible later; see [open-questions.md](open-questions.md).)
